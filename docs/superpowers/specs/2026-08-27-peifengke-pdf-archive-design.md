# “培风客”微信公众号 PDF 归档设计

日期：2026-08-27

## 目标

归档微信公众号“培风客”（微信号 `peifengke`）在执行时仍公开可访问的历史文章。每篇文章生成一个 PDF，尽量保留微信公众号原始排版、正文图片、标题、作者和发布日期。

本次归档的“全部”定义为：通过设计中列出的公开索引能够发现，且无需绕过登录、验证码、付费或其他访问控制即可取得正文的文章。已删除、仅订阅者可见、付费、被平台拦截或无法从任何公开来源恢复的文章不计为成功下载，但必须出现在失败报告中。

## 已确认需求

- 账号：培风客。
- 范围：所有可发现、公开可访问的历史文章，截至实际执行时为止。
- 输出：每篇文章一个 PDF。
- 排版：优先保留微信原文页面的排版，不统一改写成阅读模板。
- 图片：等待页面图片加载后再打印，图片嵌入 PDF。
- 更新：支持断点续传、去重和再次运行时的增量更新。
- 权限：不绕过登录、验证码、付费或其他访问控制，不要求用户提供第三方站点密码。

## 方案选择

采用“微信原文优先、公开镜像兜底”的混合方案。

只打印微信原文能够获得最高排版还原度，但原文链接可能难以枚举，部分页面也可能已失效。只依赖镜像能提高发现率，却可能丢失样式、图片或正文。混合方案先通过多个公开索引建立文章清单，再优先渲染 `mp.weixin.qq.com` 原文；原文不可访问时，才尝试正文完整的公开镜像。镜像生成的 PDF 在清单中明确标记来源，不能与微信原文归档混淆。

## 存储布局

归档产物放在仓库现有的 Git 忽略目录中：

```text
output/wechat/peifengke/
├── manifest.csv
├── failures.csv
├── run-summary.json
├── 2024/
│   └── 2024-06-18_文章标题.pdf
├── 2025/
│   └── 2025-07-08_追求自我，解放自我，表达自我.pdf
└── 2026/

```

文件名中的非法字符替换为全角或短横线，连续空白合并，标题截断时保留稳定哈希后缀。若同一天存在同名文章，也使用稳定哈希后缀消除冲突。PDF 和下载清单不提交到 Git。

## 组件边界

### 1. 索引发现器

从公开页面提取文章候选项。初始来源包括：

- “今天看啥”的培风客专栏分页；
- FreeWeChat 的培风客历史页；
- 可公开访问的其他账号索引页，用于补漏和交叉核对。

每个候选项至少包含标题、发布日期、索引来源和候选链接。发现器只读取公开页面，不登录第三方服务。单一索引不能作为“完整”的唯一依据；不同来源的候选项进入同一个清单后再去重。

### 2. 规范化与去重器

优先使用微信原文的稳定标识或规范化 URL 去重；没有原文链接时，使用“规范化标题 + 发布日期”作为次级键。相同文章来自多个索引时保留全部来源证据，并选择信息最完整的记录作为主记录。

清单状态限定为：

- `discovered`：已发现，尚未解析正文来源；
- `ready_original`：已有可访问微信原文；
- `ready_mirror`：原文不可用，但有完整公开镜像；
- `rendered`：PDF 已生成并通过基本校验；
- `failed`：本次运行无法生成有效 PDF；
- `skipped_existing`：已有通过校验的相同产物。

### 3. 来源解析器

按以下优先级选择可渲染来源：

1. 公开可访问的微信原文页面；
2. 能证明文章标题、日期和正文归属，且正文完整的公开镜像；
3. 无合格来源时记录失败，不用搜索摘要或拼接片段伪造正文。

解析器记录最终 URL、来源类型、HTTP/页面结果和失败原因。出现登录页、验证码、内容已删除、正文过短或标题不符时，当前来源判定为不可用。

### 4. PDF 渲染器

使用本机 `/usr/bin/google-chrome` 的无头打印能力渲染页面。渲染过程使用隔离的临时浏览器配置，不读取用户日常浏览器资料。

渲染器应：

- 使用适合微信公众号正文的页面宽度和默认背景图形；
- 等待正文、字体和懒加载图片稳定后再打印；
- 保留原页面正文样式，隐藏明显与文章无关的浮层、推荐模块和交互控件；
- 禁用页眉页脚中的本地临时路径；
- 为单篇文章设置超时和有限次数重试；
- 先写入临时 PDF，通过校验后再原子移动到最终文件名。

微信原文和镜像共用渲染接口，但镜像来源不得冒充微信原始排版。`manifest.csv` 中必须记录 `source_type`。

### 5. 校验与报告器

每个生成的 PDF 至少通过以下机器校验：

- 文件存在且大小超过最低阈值；
- 文件头为有效 PDF；
- 页数至少一页；
- 标题或标题的稳定片段可从渲染前页面中确认；
- 没有被识别为登录、验证码、错误或内容删除页面。

`manifest.csv` 保存每篇文章的标题、日期、发现来源、最终来源、规范化 URL、PDF 路径、状态、文件大小、内容哈希和错误信息。`failures.csv` 只列未成功归档的文章及原因。`run-summary.json` 汇总发现数、去重后数量、微信原文成功数、镜像成功数、失败数和跳过数。

## 数据流

```text
公开索引分页
  -> 提取候选文章
  -> 规范化与跨来源去重
  -> 解析微信原文或合格镜像
  -> Chrome 加载并等待资源稳定
  -> 单篇打印到临时 PDF
  -> 校验并原子落盘
  -> 更新 manifest / failures / summary
```

下载过程中每完成一篇就持久化清单，异常退出后可以从未完成状态继续。再次运行时，若规范化来源和已有 PDF 哈希均有效，则跳过；新发现文章进入正常处理流程。

## 错误处理

- 网络超时、临时 5xx 或图片加载失败：指数退避后有限重试。
- 登录、验证码、访问频控：停止该来源的激进重试，记录明确原因；不尝试规避。
- 原文删除或失效：尝试合格公开镜像；没有镜像则失败。
- 镜像正文不完整、标题不符或仅有摘要：拒绝生成 PDF。
- 单篇渲染崩溃：隔离失败，不中断整批任务。
- 磁盘空间不足或 Chrome 无法启动：停止批次，保留已完成产物和清单。

请求应串行或保持很低并发，并加入合理间隔，避免对微信和公开索引造成不必要负载。

## 测试与验收

实施时先用少量样本完成试运行，样本至少覆盖：一篇微信原文、一篇含多张图片的长文，以及一篇需要镜像兜底或明确失败的文章。

自动化测试覆盖：

- 标题和日期规范化；
- URL 规范化与跨索引去重；
- 安全文件名生成和同名冲突；
- 状态转换、断点续传和已有文件跳过；
- 登录页、验证码页、摘要页和失效页识别；
- 清单及汇总数字一致性。

样本验收通过后才运行全部历史归档。最终验收条件为：

1. 每个成功条目对应一个可打开的独立 PDF；
2. PDF 包含标题、正文及已加载的正文图片，并尽量保持原页面布局；
3. 成功、镜像兜底和失败三类结果均可从清单追溯到来源；
4. 清单中的成功数等于磁盘上通过校验的 PDF 数；
5. 再次运行不会重复下载未变化的文章；
6. 所有发现但未归档的文章都出现在失败报告中，而不是静默遗漏。

## 非目标

- 不下载付费、私密、仅登录可见或已被访问控制保护的内容；
- 不绕过验证码、风控或平台限制；
- 不保证恢复公开索引从未收录且现已删除的文章；
- 不合并成单一总 PDF；
- 不改写、摘要或重新排版正文；
- 不把归档产物提交到代码仓库。
