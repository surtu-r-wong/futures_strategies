# M02 逐合约费用与版本边界

`forward_account/fees.py` 增加 `contract-fees-v1`；原 `cost_bps` 配置沿用 `uniform-bps-v1` 的名义成交额计费。两种配置互斥，原公式不变。新费用规则按合约列出非重叠的 `valid_from/valid_to`、唯一 `rule_id`、交易所/经纪商/滑点来源；费率都必须带已知单位与非负有限JSON数值，缺项不能被补零。

|源字段|新模型 exchange 字段|语义|
|---|---|---|
|open_fee|open|普通开仓，多头/空头相同|
|offset_fee|close|普通平仓|
|short_offset_fee|close_today|平今仓|
|short_open_fee|intraday_open|日内开仓；不是开空费用|
|fee_scale|各费率unit|显式YUAN_PER_LOT、PERMILLE、PER_TEN_THOUSAND|

合约手数q、执行价p、乘数m和费率r的费用：元/手为 `abs(q)*r`；千分比为 `abs(q)*p*m*r/1000`；万分比为 `abs(q)*p*m*r/10000`。因此3手、价100、乘数10，元/手2收6元，0.6千分比和6万分比都收1.8元。没有隐含“百分比”“bp”或数值猜测。计算使用当前账户一贯的浮点算法，没有新增经纪商分笔/分单货币取整或最低费模型；这些真实规则未知时仍阻塞。

`broker` 与 `exchange` 分别持有四类费率，`broker_fee_basis` 只接受 `additional_to_exchange`。报价是含交易所费用的经纪商总费率时，必须先由来源确认可分拆口径，不能把总费率再叠加交易所费。`slippage` 独立列示、每个成交分拆项收取，若执行价已含滑点，不可再默认为额外滑点；`excluded_costs` 必须显式声明。审计成交中的 `exchange_fee/broker_fee/slippage_fee` 和两项开仓调整之和等于 `fee`，成交费用之和进入当日NAV，再检查保证金是否足够。

净持仓采用 `dated-net-lots-v1`、FIFO：增加同向数量开仓；减少数量逐批平仓；反手先平掉原方向再开反方向。每批保存开仓交易日/时间、数量、开仓价、乘数、源证据和当时费用规则散列。按真实开仓交易日区分隔日/平今，既不按多空区分开仓费，也不按文件mtime猜持仓年龄。原持仓数量、方向、日期、费用规则必须与持仓批次一致，否则拒绝。

目前支持的日内开仓处理是显式政策 `ordinary_open_then_same_day_adjustment`：开仓时先收普通开仓费；当天关闭的数量在平今时按原开仓成交价计算“日内开仓费−已收普通开仓费”的调整，隔日平仓不调整。政策和来源必须明确，真实候选 `policy_source=null`，未把该实现假定为交易所既有政策。例如当天2手在100开仓，乘数10、普通开仓2‰/日内开仓1‰，在200平今时开仓调整仍为−2元，不按平仓价误算为−4元。J和LH日内开仓值不同的事实已保留，不能直接视为开空加费。

账户仍只支持日历给定的每日一次日盘执行与日结，没有新增夜盘/盘中撮合接口。纯费用函数覆盖同日多次增减/平今的合成验证；现有逐日账户自然产生的持仓减少属于隔日平仓，不能把函数测试说成完整盘中实盘接入。手续费规则按交易日生效，不支持同日盘中切换费率。

67合约乘数及保证金从本地原始证据和汇总CSV交叉校验；本批次多空保证金全部一致。所有日期窗口仅为2026-10-15，不能继承到下一交易日。19个CZCE原始三位年月代码通过交易所+合约匹配到原生四位代码，保留原始symbol作为旁证；独立生命周期66条，唯一缺项EC2611.INE。48个CNY/报价维度只是候选假设，候选不得执行。费率以带明确fee_scale的settlement_rules为源，contract_info中的`日内开仓手续费=-1`等原样保留在旁证，不当零或取绝对值替代。

旧账存储仍由不可变配置、账户版本和引擎文件指纹保护。此版本变更后，旧SQLite直接advance会拒绝，不能从无日期旧持仓自动推算新批次。费用规则不能通过 `extend_references` 改写，若需要新增日期规则应预先声明或另行设计经批准的迁移；新增合约也必须在费用配置中覆盖。ReturnFeed不改schema，使用不同策略version（账户版本+配置散列+引擎散列）分开输出，fee_model文本明确新旧版本和新费表散列；不拼接旧研究或旧账户收益。
