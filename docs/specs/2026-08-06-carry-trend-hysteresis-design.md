## 1. 问题（实测归因，2026-08-06）

全历史基准（2013-01-04 → 2026-04-29，3227 个交易日）：净年化 5.89%、夏普 0.371、
最大回撤 44.70%；毛年化 14.48%、毛夏普 0.914。**差距几乎全是成本。**

逐项归因结论：

| 候选 | 实测 | 判定 |
|---|---|---|
| 三档吊灯止损 | 触发 661 次，占 37,005 笔交易的 1.79%；98.34% 持仓日满档 | **不是问题** |
| 动量/缩量过滤砍掉信号 | 砍掉 31.4% 信号，但被砍组前向收益全尺度更差（20d 0.41% vs 1.0 档 0.59%） | **砍对了，别放松** |
| 波动率缩放 | 实际年化波动 15.89% vs 目标 15% | **正常** |
| **过滤器抖动** | 见下 | **元凶** |

`signals.py:137-166` 用 `main_close` vs `price_ma`（10 日）做**布尔**判定，`strength`
归零即 `effective_direction` 归零、全额平仓。价格在均线附近震荡时状态反复翻转：

- 平仓中 **83.6%**（4,800 / 5,743）发生时 Carry 排名仍指向同方向 —— 观点没变
- 其中 **43.6% 在 1 个交易日内**原方向重新进场，68% ≤3 天，88.4% ≤10 天
- 持仓周期中位数 **3 天**，26.8% 仅 1 天（对 10 日均值的慢变量而言不合理）
- 换手结构：`entry` 37.9% + `signal_exit` 36.1% = **74%**（`rebalance` 仅 15.7%）
- 这些往返 = **53.3% 的全部换手** = **年化 4.16% 成本**（总成本 7.79%/年）

消除抖动的收益上界约 ann 10.05%（未计价格变动导致的信号本身变化）。

**已排除的路**：加再平衡阈值（no-trade band）无效 —— `rebalance` 笔数占 66% 但换手
仅占 15.7%，band 开到 0.05 也只省 4.8% 换手。

## 2. 目标与非目标

目标：在**不放松过滤器判别力**的前提下，消除阈值附近的状态抖动，降低换手成本。

非目标：
- 不改 Carry 排名、选池、ATR 风险预算、波动率缩放、杠杆上限、止损
- 不追求提高毛收益；毛夏普 0.914 是信号质量的体现，本次只针对成本
- 不改变"次日开盘执行"的执行口径

## 3. 机制

引入 per-product 的**趋势状态** `trend_state ∈ {-1, 0, +1}`，表达价格相对均线的
**绝对**趋势（与 Carry 方向无关）。两个新参数：

| 参数 | 默认 | 含义 |
|---|---|---|
| `trend_band_atr` (k) | `0.0` | 缓冲带半宽，单位为该合约 ATR |
| `trend_confirm_days` (N) | `1` | 切换所需的连续同侧确认天数 |

统一转移规则（同时表达 ATR 缓冲带与连续确认）：

```
upper = price_ma + k * atr
lower = price_ma - k * atr
side  = +1 if close > upper else (-1 if close < lower else 0)

若 side != 0 且该 product 最近 N 个曲线行的 side 全等于 side:
    trend_state = side
否则:
    trend_state 保持不变（初始 0）
```

`price_ma` 或 `atr` 非有限时不更新状态（该行本就 `input_ready=False`，不产生信号）。

消费端把原先的布尔判定换成状态比较，其余不动：

```
trend_aligned = (direction == trend_state)     # 原: direction==1 and close>ma ...
trend_opposed = (direction == -trend_state)
```

`strength` 三档取值（1.0 / 0.5 / 0.0）与量价双缩条件**保持原样**。

## 4. 向后兼容

k=0 且 N=1 时：`upper = lower = price_ma`，`side = sign(close - price_ma)`，
`trend_state` 每日直接取 side —— 与现行无状态逻辑逐点等价，包括
`close == price_ma` 落入 `side = 0`（既不 aligned 也不 opposed → `strength = 0`）
这一边缘情况。**默认参数下全历史结果必须与基准逐日一致**，作为验收项。

## 5. 实验矩阵

方案 A（ATR 缓冲带）：k = 0.25 / 0.5 / 1.0，N = 1
方案 C（连续确认）：N = 2 / 3 / 5，k = 0
基准：k = 0，N = 1

每组全历史约 5 分钟、峰值 2.3 GB。**串行跑**（见 CLAUDE.md 与内存约束）。

对比口径：净年化、净夏普、最大回撤、总换手、年化成本、持仓周期中位数、
过滤器诱发平仓占比、毛夏普（确认信号质量未被破坏）。

## 6. 测试

1. k=0/N=1 逐点复现原判定（含 `close == ma` 边缘）
2. 带内维持原状态；突破上带→+1、下带→-1
3. 连续确认：N=3 时 2 天同侧不切换、3 天才切换
4. 跨 product 状态相互独立
5. `price_ma` / `atr` 缺失时状态不更新
6. 现有 `tests/` 全绿（默认参数不改变任何行为）
7. 全历史默认参数与 `output/carry_base.xlsx` 逐日净值一致

`signals` 表新增 `trend_state` 列以便审计。
