# CICSF023：把仓单换成交易所原始档案，并把有效预报加进去

设计日期：2026-09-22。引擎 `citic_index`（与 025 / 026 / 027 同一条）。
起因：用户 2026-09-22 指示——数据库已补入交易所来源的仓单数据，其中应有有效预报，
把仓单与有效预报加总后重跑，看绩效有无改善。

## 1. 为什么这件事只能靠新数据源问

023 的因子是

    TS_it = mean(C, 最近 p 日) / mean(C, t−299..t−200) − 1

`C` 是标准仓单数量。现有输入 `data/citic_023/receipts.csv` 来自
`commodity_research` catalog v2 的 66 条 Wind series（`source='wind'`，
名称形如「注册仓单量:豆一」「库存期货:铝」「仓单数量:苹果」），**只有已注册仓单**。

**有效预报（已申报入库、尚未注册成仓单的量）只有郑商所公布**。上期所、大商所、
广期所的日报里没有这一列——这不是采集缺漏，是交易所本来就不发。所以：

- 用户的假设**只可能在郑商所品种上起作用**；
- 而它在那些品种上量级不小：预报/仓单的历史比值 PK 1.25、RS 0.78、LR 0.57、
  OI 0.41、SA 0.40、WH 0.26、SF 0.26——足以改变横截面排序。

## 2. 数据源：`exchange_data.warehouse_source_*`

办公室 2026-09-21 入库的交易所直抓档案（请求函 `2026-09-18-user-exchange-data-all-into-db`）：
`warehouse_source_capture` 32,561 份原文 + `warehouse_source_record` 4,318,562 条解析行，
八个来源（SHFE 日报/周报、CZCE 新旧两版、DCE 仓单/升贴水、GFEX、SHFE 升贴水），
2008-01 起。**它是原文档案不是库存序列**——办公室处置单原话「不能当已入库/可加总库存」。
派生层要我们自己建，落在 `citic_index/exchange_receipts.py`，规则逐条对应档案里实见的形态：

| 交易所 | 取哪一类行 | 仓单列 | 预报列 |
|---|---|---|---|
| CZCE（TEXT + LEGACY） | `TOTAL` | `仓单数量` / `仓单数量(完税)`+`(保税)` / `确认书数量` | **`有效预报` / `有效入库预报` / `预报数量`** |
| DCE | `SUMMARY` | `current_quantity` | 无 |
| GFEX | `SUMMARY`（品种码为空的总计行丢弃） | `current_quantity` | 无 |
| SHFE | `SOURCE_ROW` 明细加总 | `期货` | 无 |

四个已实现并被测试钉住的坑：

1. **`COMBINED_TOTAL` 是派生重复行**（MA 的「完税+保税」），加上去品种翻倍。
2. **同段多个 `总计`**：PF 在 2021-04..09 每个品牌表各出一个 `总计`、最后再出一个总的，
   三行结构完全相同（同 `总计` 单元格、同 section position、同 label），只能按算术判：
   **末行等于前面之和时，末行是合计，只取它**。全档案里所有同列多总计的品种日都是这个形态，
   共 102 次（其余不服从的 563 个「品种日」是 2010–2012 无品种码的行，本来就不进序列）。
3. **郑商所改过品种码**：`ME/RO/ER/TC/WS/WT → MA/OI/RI/ZC/WH/PM`，
   并且 **`TA` 在 2022-11-25 之后写成 `PTA`**。不映射的话 TA 的序列 2022 年当场断掉、
   旁边冒出一个幽灵品种——而因子是拿今天除以 200 天前的基线，**品种自己序列内的断裂正是
   唯一能动排序的那种错**。
4. **空白不是零**：档案把每个单元格按交易所原样存成字符串，非数值单元格贡献 NULL 而不是 0；
   哪些缺席该补零由 `citic_index/receipts.fill_absent_zeros` 判（DCE 写一个 0 之后就不再发行），
   派生层先造一个零出来会把那层的判据废掉。

SHFE **不在本次取数范围**，理由写在脚本里：它的明细行在历史上换过三种形态
（2008–2014 旧 HTML 带 `product_label`+`期货`；2014-05-19..2025-11-17 的 JSON 接口
把标签留空、品种在 `dimensions.VARNAME`、量在 `WRTWGHTS`，占 688,261 行即大半历史；
2025-11-18 起回到标签但拆 仓库/厂库），要三个解析器，**而它一分预报都不增加**。
因子按品种自比 ⇒ 别的品种来自哪个源不可能动某个品种的排名，只有品种内断裂会。

## 3. 校验：拿 Wind 当独立裁判

同一批仓单有两个独立测量。派生层写完先与 Wind 逐值对，不对就不看绩效：

- **43 个重叠品种里 42 个比值恰好 1.0000、相关 1.0000、100% 落在 1% 内**
  （87,787 个重叠品种日）。
- **PK 是唯一例外，且解释是精确的**：`wind == 交易所仓单 + 有效预报`，
  1,219 天 **100%** 成立 ⇒ Wind 给 PK 编的两条 `sum_component`（厂库 / 车船板）
  实际等于「仓单+预报」。**基线里已经有预报的品种只有 PK 一个。**
- ZC 两边恒为 0（动力煤仓单确实是 0），不是缺陷。

两个发现都是这道裁判抓出来的：PF 翻倍（第 2 条坑）与 PTA 断裂（第 3 条坑），
修完才有上面的 42/43。

## 4. 臂的设计

一次只动一件事，不然「改善」归因不了。全部用同一份 `prices.csv`、同一窗口、
同一预注册 p 网格（1,3,5,10,20,40,60）、开放宇宙、结算价口径、T+1 成交。

| 臂 | 仓单来源 | 品种池 | 隔离出什么 |
|---|---|---|---|
| **A** | Wind（现状 `receipts.csv`） | 65 | 控制臂，必须复现已知数 |
| **B0** | 交易所（43 个）+ Wind（22 个 SHFE/INE） | 65 | **只换源**：覆盖与日期差异 |
| **C0** | 同 B0，**加有效预报** | 65 | **只加预报**（与 B0 同宇宙） |
| **B** | 再加交易所独有的 12 个品种 | 77 | 宇宙变宽 |
| **C** | 同 B，加有效预报 | 77 | 宽宇宙下的预报效应 |

判据与 023 原复刻一致：**与官方 CICSF023.WI 的日收益相关系数为主判据**，夏普为次；
两者分歧时以相关为准（这条路径的目标是那条序列，不是收益）。
全网格都报，不只报选中点。
